# BrightEyes Handoff — 2026-07-01

## What changed today

- Fixed a potential null-risk in the save-options path.
- Cleaned up Meson build warnings and made the build tolerate missing optional files more gracefully.
- Built and verified an installable RPM artifact locally.
- Improved viewer zoom behavior so mouse-wheel zoom is anchored more naturally and gated behind `Ctrl`.
- Tuned OCR in several directions, then rolled those heuristics back after they reduced output quality on mixed-content images.
- Added a full-image OCR warning so users are nudged toward selection OCR for images that mix text and graphics.

## Current OCR behavior

- Selection OCR is the preferred path for screenshots, listings, and other mixed layouts.
- Full-image OCR now shows a warning before it runs.
- If the user continues, BrightEyes uses the simpler OCR path again instead of the heavier heuristic pipeline.
- The current goal is to preserve the better text quality from the earlier, simpler OCR behavior rather than forcing stricter filtering.

## Code areas touched

- `src/window.c`: OCR entry points, selection flow, warning dialog, and file-action wiring.

## General coding notes

- Keep OCR changes small and test on the exact image class that triggered the issue.
- Selection OCR is safer than full-image OCR when the image contains both text and artwork.
- Prefer in-memory processing for OCR and image transforms.
- Use `meson compile -C build` as the quick validation step after code changes.
- Avoid checking in generated artifacts like RPMs unless packaging work specifically needs them tracked.
